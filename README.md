# 집온 JipOn - 서비스 이용 설정

## 사용자와 목표
- 사용자: 청소 서비스 이용을 희망하는 사람
- 목표: 청소 서비스 종류를 확인하고 서비스를 신청한다.

## 사용자의 흐름
1. 개인정보 제공에 동의하고 '서비스 신청하기' 버튼을 누른다
2. 신청하고자 하는 청소 서비스를 문의 제목에 입력한다. 비어있으면 같은 단계에서 안내를 받는다.
3. 청소 서비스 이용 시간을 선택하고 필요하면 추가 문의를 포함한다.
4. 제목, 시간, 추가 문의를 확인하고 수정하거나 완료한다.
5. 설정 완료 안내를 확인하고, 필요하면 재설정 한다.

## 인터렉션 시나리오
1. 시작과 개인정보 동의 안내
- 행통, 이벤트: 기존 동의 체크박스를 선택하고 '서비스 신청하기'를 클릭한다.
- 조건: 개인정보 제공 동의가 선택되었는가?
- 반응, 다음 상태: 동의 전에는 버튼을 누를 수 없다. 동의 후 클릭하면 사용 목적을 설명하는 안내 팝업이 열린다.
             팝업에서 '돌아가기'를 누르거나 Esc를 누르면 동의를 해제하고 시작 화면에 남는다.
            '동의하고 설정 시작하기'를 누르면 제목 입력 화면을 연다.

2. 제목 입력
- 행동, 이벤트: 제목을 적고 '상세 조건 선택하기'를 클릭한다. 
- 조건: 앞뒤 공백을 지운 제목이 비어 있는가?
- 반응, 다음상태: 비어있으면 같은 화면에 오류를 표시하고 입력창에 초점을 둔다.
                값이 있으면 저장하고 조건 선택으로 이동한다.

3. 조건 선택
- 행동, 이벤트: 서비스 이용 시간을 바꾸나 추가 문의를 선택하고 '내용 확인하기'를 클릭한다.
- 조건: 질의응답을 선택했는가?
- 반응, 다음상태: 선택했을 때만 질문 수를 보여준다

4. 내용 확인
- 행동, 이벤트: 제목, 시간, 추가 문의를 읽고 '수정하기' 또는 '설정 완료하기'를 클릭한다.
- 조건: 수정인가, 완료인가?
- 반응, 다음상태: 수정하면 기본 값을 유지하고 조건 선택으로 돌아간다.
                완료하면 완료 안내로 이동한다.

5. 완료와 재설정
- 행동, 이벤트: 완료 안내를 읽고 필요하면 '다시 설정하기'를 클릭한다.
- 반응, 다음상태: 새 설정의 제목, 시간, 추가 문의, 진행 상태를 초기화 하고 제목 입력부터 다시 시작한다.
                이미 확인한 개인정보 제공 동의와 다른 기능을 유지한다.

6. 중간고사 기능 추가 항목(서비스 이용 준비 체크리스트) 설명
- 행동, 이벤트: '방문 전 준비하기'를 누르고 준비 항목을 체크한다.
- 조건: 체크한 항목이 전체 항목과 일치하는가?
- 반응, 다음 상태: 체크할 때마다 완료 항목 수와 진행률이 변경된다.
                4개 항목을 모두 체크하면 완료 안내가 표시된다.
                체크 해제나 초기화 버튼으로 상태를 수정할 수 있으며, '신청 완료 화면으로'를 누르면 이전 화면으로 돌아간다.

7. 테스트 기록
- 정상 경로: 신청 완료 화면에서 체크리스트로 이동하고, 항목 체크 및 전체 완료 안내를 확인.
- 수정 경로: 체크 해제 및 초기화 후 진행률이 정상적으로 변경되는 것을 확인.
- 이전 화면 이동: 신청 완료 화면으로 정상 복귀하는 것을 확인.

## 10주차 코드 내용
0. 추가 및 수정
- 네비게이션 메뉴 개선: 전체 서비스, 이용 방법, 신청 내역으로 메뉴를 구성하고 각 메뉴 클릭 시 해당 - 섹션으로 이동하도록 수정
- 현재 위치 표시: 페이지 이동에 따라 현재 활성화된 메뉴를 시각적으로 표시
- 모바일 메뉴 개선: 모바일 화면에서 메뉴 열기/닫기 기능 및 메뉴 선택 후 자동 닫힘 적용
- 신청 내역 상태 필터: 전체, 저장됨, 취소됨 기준으로 신청 내역을 구분하여 조회
- 빈 결과 상태 동기화: 필터 선택 결과에 따라 빈 결과 안내 문구와 서비스 신청 이동 버튼을 변경
- 접근성 개선: 메뉴 및 필터 상태를 aria-current, aria-expanded, aria-pressed 속성으로 반영

1. 메뉴별 목적지
- 전체 서비스 → #about: 집온의 주요 홈케어 서비스 안내
- 이용 방법 → #planner: 서비스 신청 및 상세 조건 설정
- 신청 내역 → #archive: 저장된 신청 내역 확인 및 상태 관리

2. 필터 기준
- 전체: 저장된 모든 신청 내역 표시
- 저장됨: 취소되지 않은 신청 내역 표시
- 취소됨: 취소 처리된 신청 내역 표시

3. 기능 확인 방법
- 상단 네비게이션 메뉴를 클릭하여 각 섹션으로 이동하고 현재 메뉴 표시가 변경되는지 확인
- 모바일 화면으로 전환하여 메뉴 열기/닫기 및 메뉴 선택 후 자동 닫힘 확인
- 서비스 신청을 완료하여 신청 내역에 저장되는지 확인
- 신청 내역에서 전체, 저장됨, 취소됨 필터를 각각 선택하여 표시 결과 확인
- 신청 내역이 없는 상태에서 필터를 변경하여 빈 결과 안내 문구와 버튼이 필터 상태에 맞게 변경되는지 확인

## 11주차 코드 내용
0. 추가 및 수정 기능
- 색상 대비 개선: 텍스트와 배경의 색상 대비를 점검하고, 입력 오류 및 선택 상태를 색상과 안내 문구로 구분
- 대체 텍스트 및 라벨 추가: 메인 이미지에 alt 텍스트를 추가하고, 입력 항목과 버튼에 명확한 라벨 및 기능 설명 적용
- 키보드 접근성 개선: 본문 바로가기 기능 추가, 키보드 초점 표시 및 메뉴 닫기(Esc) 기능 적용
- 현재 상태 안내: 메뉴 이동 및 신청 내역 필터 상태를 접근성 속성으로 전달
- 안내 메시지 개선: 입력 오류, 신청 결과 및 필터 조회 결과를 명확한 문구로 안내

1. 접근성 개선
- 본문 이동 시 상단 메뉴를 거쳐야 함 → 키보드 사용자를 위한 '본문 바로가기' 기능 추가
- 이미지의 대체 텍스트가 없음 → 이미지 내용을 설명하는 alt 텍스트 추가
- 입력 오류를 색상으로만 구분 → 오류 문구와 aria-invalid 속성을 함께 적용
- 키보드 초점 위치를 확인하기 어려움 → :focus-visible을 활용해 초점 표시 강화

## 12주차 코드 내용
1. UI 컴포넌트 구현
- 모달(Modal): 저장된 신청 내역의 상세 정보를 확인할 수 있도록 구현. 신청 내역 카드의 '내용 보기' 버튼을 클릭하면 모달이 열리고, 닫기 또는 확인 버튼으로 종료 가능
- 접힘/펼침 UI(Accordion형): 상세 조건 선택 단계에서 '추가 문의도 있어요'를 선택하면 추가 문의 항목이 펼쳐지고, 선택을 해제하면 다시 접힘

2. 사용자 조작 및 상태 변화
- 신청 내역의 상태에 따라 저장됨/취소됨 표시와 취소 및 되돌리기 버튼의 문구 변경
- 추가 문의 선택 여부에 따라 관련 입력 항목의 표시 및 활성화 상태 변경

3. 재사용 가능한 구조
- 공통 버튼과 신청 내역 카드에 CSS 클래스를 적용하여 디자인 및 스타일 관리
- createText(), createPlanCard() 함수를 활용해 반복되는 신청 내역 카드와 텍스트 요소를 재사용 가능한 구조로 구현
- 이벤트 위임 방식을 적용해 신청 내역의 상세 보기 및 상태 변경 기능을 공통 이벤트로 처리

4. 접근성 적용
- 모달에 aria-labelledby와 명확한 닫기 버튼 이름을 적용하고, 키보드 조작을 지원
- 추가 문의 영역에 aria-expanded, aria-controls를 적용하여 펼침 상태를 전달하고, 버튼에 명확한 기능명을 사용
